# Robot_set 数据共享机制

## 一句话

`Robot_set` 是这个系统的**数据黑板**——所有模块通过 `shared_ptr` 共享同一个对象，各写各的字段，各读各的，约定单写者，不加锁。

---

## 一、Robot_set 结构（数据总线）

位置：[include/robot.hpp:8-84](../GKD_Control/include/robot.hpp#L8-L84)

```cpp
struct Robot_set {
    // ─── 组1：底盘移动指令 ───
    fp32 vx_set;          // 前后速度 (m/s)，前为正
    fp32 vy_set;          // 横向速度 (m/s)，左为正
    fp32 wz_set;          // 旋转速度 (rad/s)，逆时针为正
    bool spin_state;      // 是否正在自旋
    bool chassis_recover_mode; // 底盘恢复模式（断电后归零）

    // ─── 组2：云台控制指令 ───
    fp32 gimbal1_yaw_set;      // 1号云台 yaw 目标角度
    fp32 gimbal1_pitch_set;    // 1号云台 pitch 目标角度
    fp32 gimbal2_yaw_set;      // 2号云台 ...
    fp32 gimbal2_pitch_set;
    fp32 gimbal3_yaw_set;
    fp32 gimbal3_pitch_set;

    // ─── 组3：云台反馈（云台 → 底盘）───
    fp32 gimbalT_1_yaw_reletive;  // 云台相对底盘的 yaw 角度（底盘运动学用）

    // ─── 组4：射击指令 ───
    bool friction_open;         // 摩擦轮开关
    int  shoot_open;            // 射击权限（0=禁止，1=云台1，2=云台2，3=双云台）
    bool cv_fire;               // 视觉自瞄开火信号
    bool auto_aim_status;       // 自瞄状态

    // ─── 组5：外部反馈 ───
    Types::Referee_info referee_info;               // 裁判系统数据
    Types::ReceivePacket_Super_Cap super_cap_info;  // 超级电容数据
    Types::ROBOT_MODE mode;                         // 当前机器人模式
};
```

## 二、生命周期

### 创建

位置：[src/robot_controller/robot_controller.cc:12-19](../GKD_Control/src/robot_controller/robot_controller.cc#L12-L19)

```cpp
Robot_ctrl::Robot_ctrl() : ... {
    robot_set = std::make_shared<Robot_set>();  // ← 唯一创建点
}
```

`make_shared` 一步完成：在堆上 `new Robot_set` + 包装成 `shared_ptr`。

### 分发 — init() 传指针

位置：[src/robot_controller/robot_controller.cc:27-36](../GKD_Control/src/robot_controller/robot_controller.cc#L27-L36)

```cpp
void Robot_ctrl::start_init() {
    rc_controller.init(robot_set);  // shared_ptr 拷贝，引用计数 +1
    referee.init(robot_set);        // shared_ptr 拷贝，引用计数 +1
    chassis.init(robot_set);        // shared_ptr 拷贝，引用计数 +1
    gimbal.init(robot_set);         // shared_ptr 拷贝，引用计数 +1
}
```

各模块内部保存：

```cpp
// 各模块的成员变量
std::shared_ptr<Robot::Robot_set> robot_set;  // 存储一份拷贝

void init(const std::shared_ptr<Robot::Robot_set>& robot) {
    robot_set = robot;  // 共享同一对象
}
```

最终所有模块的 `robot_set` 都指向**同一个 `Robot_set` 对象**。

```
Robot_ctrl.robot_set ──→ [Robot_set 对象]  ←── chassis.robot_set
                                        ↑
                         gimbal.robot_set ──┤
                         referee.robot_set ─┤
                         rc_controller.robot_set
```

### 销毁

最后一个持有 `shared_ptr` 的对象析构时，自动释放 `Robot_set`。

## 三、读写约定：单写者，不加锁

**核心规则**：每个字段只有一个线程写，多个线程可以读。不依赖 mutex。

### 为什么安全？

1. **单写者**：不会有两个线程同时写同一个字段
2. **容忍一帧延迟**：读差 2ms 不影响控制
3. **简单类型**：`fp32`、`bool`、`int` 赋值是原子的（在 ARM/x86 上）

### 完整读写关系表

| 字段 | 写入者（写线程） | 读取者（读线程） |
|------|-----------------|-----------------|
| `vx_set` | RC_Controller (串口回调) | Chassis::task() |
| `vy_set` | RC_Controller (串口回调) | Chassis::task() |
| `wz_set` | RC_Controller (串口回调) | Chassis::task() |
| `spin_state` | Chassis::task() | RC / UI |
| `chassis_recover_mode` | Chassis::task() | Chassis 自身 |
| `gimbalT_1_yaw_set` | RC (鼠标) / 视觉Socket回调 | GimbalT::task() |
| `gimbalT_1_pitch_set` | RC (鼠标) / 视觉Socket回调 | GimbalT::task() |
| `gimbalT_1_yaw_reletive` | GimbalT::update_data() | Chassis::decomposition_speed() |
| `friction_open` | RC_Controller (串口回调) | Shoot::task() |
| `shoot_open` | RC / 视觉回调 | Shoot::task() |
| `cv_fire` | 视觉Socket回调 | Shoot::task() |
| `auto_aim_status` | RC_Controller | GimbalT |
| `mode` | RC / Socket回调 | Chassis, GimbalT |
| `referee_info` | Dji_referee::task() | RC_Controller, Chassis, Power |
| `super_cap_info` | Super_Cap::task() | Power Manager |

## 四、跨线程数据流实例

### 示例：键盘 W 前进

```
线程1：io<SERIAL> 的 task 线程
  │
  ├─ read(串口) → 收到 ReceivePacket_RC_CTRL
  ├─ callback → RC_Controller::unpack()
  └─ robot_set->vx_set = 1.0;        ← 写入

线程2：Chassis::task() 循环 (500Hz)
  │
  ├─ decomposition_speed()
  │   ├─ 读 robot_set->vx_set        ← 读到 1.0
  │   ├─ 读 robot_set->vy_set        ← 读到 0
  │   ├─ 读 robot_set->wz_set        ← 读到 0
  │   └─ 读 robot_set->gimbalT_1_yaw_reletive
  ├─ 麦轮分解 → wheel_speed[4]
  ├─ PID → wheels_pid[i].set()
  └─ motors[i].give_current = pid_out  → CAN → 电机转动
```

### 示例：视觉自瞄覆盖云台角度

```
线程1：io<SOCKET> 的 task 线程
  │
  ├─ recvfrom() → 收到 Auto_aim_control 包
  ├─ callback_key → lambda
  └─ *yaw_set = vc.yaw_set;          ← 写入 gimbalT_1_yaw_set
     *pitch_set = vc.pitch_set;      ← 写入 gimbalT_1_pitch_set

线程2：GimbalT::task() 循环 (1000Hz)
  │
  ├─ update_data()
  ├─ *yaw_set >> yaw_absolute_pid >> yaw_motor     ← 读到视觉的目标角度
  ├─ *pitch_set >> pitch_absolute_pid >> pitch_motor
  └─ 云台转动，对准目标
```

## 五、关键设计要点

### 1. 用 shared_ptr 不用 raw 指针

```cpp
// ✅ 安全：引用计数保证不悬空
std::shared_ptr<Robot_set> robot_set;

// ❌ 危险：不知道谁最后一个用，谁负责释放
Robot_set* robot_set;
```

### 2. 初始化列表保证成员先构造

```cpp
Robot_ctrl::Robot_ctrl()
    : rc_controller(串口名),    // ← 先构造成员
      gimbal(云台配置),
      chassis(底盘配置)         // 这些构造时 robot_set 还没创建！
{
    robot_set = make_shared<Robot_set>();  // ← 然后才创建 Robot_set
    // 之后在 start_init() 里分发给各模块
}
```

### 3. 字段分组降低心智负担

不需要加锁，因为：

```
vx_set 只在 RC_Controller::unpack 里写 → 单写者
yaw_reletive 只在 GimbalT::update_data 里写 → 单写者
mode 虽有多个写入点，但都有上下文保护（按键触发，不会同时）
```

### 4. 新增字段只需三步

1. 在 `Robot_set` 里加字段
2. 确定谁是唯一写入者
3. 读取者直接读

不需要改任何锁、队列、IPC。

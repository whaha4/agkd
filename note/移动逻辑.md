GKD 机器人移动逻辑分析指南
这个项目的移动逻辑分为 5 层，从上到下依次是：


遥控器/自动瞄准 → Robot_set (目标速度) → 速度分解 → PID 速度环 → 功率限制 → 电机电流输出
1. 整体架构——先看懂"数据流"
入口在 main.cc：


Robot::Robot_ctrl robot;
robot.load_hardware();   // 加载 CAN / Serial / Socket 硬件
robot.start_init();      // 初始化各模块 (chassis, gimbal, referee...)
robot.start();           // 启动各子系统的独立线程
Robot_ctrl（robot_controller.hpp）持有三个核心模块：

Chassis::Chassis chassis — 底盘移动
Config::GimbalType gimbal — 云台控制
Device::Rc_Controller rc_controller — 遥控器输入
start() 时，每个模块跑在独立线程里（robot_controller.cc:49-51）：


threads.emplace_back(&Chassis::Chassis::task, &chassis);  // 底盘线程
threads.emplace_back(&Config::GimbalType::task, &gimbal); // 云台线程
2. 核心数据结构——Robot_set（共享状态）
所有模块通过 shared_ptr<Robot_set> 共享状态（robot.hpp）。移动相关字段：

字段	含义	单位
vx_set	目标前进速度（前为正）	m/s
vy_set	目标横向速度（左为正）	m/s
wz_set	目标旋转角速度（逆时针为正）	rad/s
gimbalT_1_yaw_reletive	云台相对底盘的 yaw 角度	rad
遥控器写入 vx_set / vy_set / wz_set，底盘线程读取并执行。

3. 移动核心——Chassis::task() 主循环
这是最关键的函数，在 chassis.cc:46-133。控制频率 = 500Hz（ControlTime = 2ms）。

主循环每 2ms 做以下事情：


┌─ 裁判系统断电？ → 所有电机清零，continue
│
├─ decomposition_speed()  ← 速度分解（场心坐标系 → 车身坐标系）
│
├─ ROBOT_NO_FORCE 模式？ → 电机清零
│
├─ 速度限幅（max_wheel_speed = 2.5 m/s）
│
├─ 对每个轮子跑 PID 速度环 → wheels_pid[i].set(wheel_speed[i])
│
├─ 功率限制 → power_manager.getControlledOutput()
│
└─ 输出电流到电机 → motors[i].give_current
4. 速度分解 decomposition_speed() —— 麦克纳姆轮运动学
chassis.cc:135-202 ，这是移动逻辑最核心的数学。

第 1 步：坐标系旋转（场心 → 车身）

sincosf(robot_set->gimbalT_1_yaw_reletive, &sin_yaw, &cos_yaw);
vx_set = cos_yaw * robot_set->vx_set + sin_yaw * robot_set->vy_set;
vy_set = -sin_yaw * robot_set->vx_set + cos_yaw * robot_set->vy_set;
遥控器给的 vx_set / vy_set 是场心坐标系（前=场地前方），但底盘是旋转的。所以用云台 yaw 角度做旋转矩阵变换到车身坐标系（前=车头方向）。

第 2 步：Wz 方向处理（底盘跟随云台 + 小陀螺）
这段比较复杂，分三种情况：

条件	行为
wz_set ≠ 0（遥控器直接控制旋转）	直接使用遥控器 wz_set，记录方向	
wz_set = 0 且 recover_mode（刚恢复供电）	用 PID 把云台角度归零到 0	
wz_set = 0 正常模式	用 PID 让小底盘自动跟随云台方向（角度误差 → PID → wz_set）	
这里的 chassis_angle_pid 是一个 PidRad + Invert 串联控制器（chassis.cc:26-32）：


chassis_angle_pid = PidRad(config, yaw_reletive) >> Invert(follow_dir);
PidRad 处理角度误差（自动处理 ±π 环绕）
Invert 反转方向
还有一段"小陀螺"逻辑（chassis.cc:170-184）：当用户刚释放旋转摇杆，底盘还在惯性旋转时，如果云台角度在 0.1~0.6 rad 之间，逐渐减速；超过 0.6 rad 继续原方向。

第 3 步：麦克纳姆轮速度分解

wheel_speed[0] = -vx_set - vy_set + wz_set;  // 左前
wheel_speed[1] = -vx_set + vy_set + wz_set;  // 左后
wheel_speed[2] =  vx_set - vy_set + wz_set;  // 右前
wheel_speed[3] =  vx_set + vy_set + wz_set;  // 右后
这是麦克纳姆轮逆运动学公式。由 vx/vy/wz（车身坐标系）算出四个轮子的线速度。

物理含义：

vx_set：前后运动分量，四轮同号
vy_set：左右运动分量，对角轮同号、相邻轮反号（麦克纳姆轮特性）
wz_set：旋转分量，四轮同号叠加
5. PID 速度控制
每个轮子有一个 PidPosition 控制器（pid_controller.cc:7-19）：


error = 目标速度 - 实际速度;
Pout = kp * error;
Iout += ki * error;        // 积分累加，防静态误差
Dout = kd * (error - last_error);  // 微分，抑制震荡
out = clamp(Pout + Iout + Dout, -max_out, +max_out);
Hero 车型的轮速 PID 参数（config_hero.hpp:41-47）：


kp=15000, ki=10, kd=0, max_out=14000, max_iout=2000
Kp 极大 → 快速响应
Ki 很小 → 缓慢消除稳态误差
Kd=0 → 不微分（轮子惯性大，不易震荡）
max_out=14000 对应 DJI 电机电流指令上限
6. 功率限制 Power::Manager
power_controller.hpp 实现了能量环功率分配，保护裁判系统不超功率：

功率模型：P_wheel ≈ τ*ω + k1*|ω| + k2*τ² + k3/4
在线辨识：用 RLS（递推最小二乘法）实时更新 k1, k2
功率分配：超功率时，优先保证控制误差大的轮子获得更多电流
超级电容：提供额外 300W 缓冲
注意目前在 chassis.cc:126 功率限制被注释掉了，直接输出 PID 结果：


motors[i].give_current = wheels_pid[i].out;  // 直接用PID输出
// motors[i].give_current = cmd_power[i];    // 功率限制后输出（被注释）

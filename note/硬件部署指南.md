# 硬件部署指南

> 主控板 = Mini PC，只有一台。视觉和控制代码都跑在上面。

---

## 一、硬件架构总览

```
                    Mini PC (主控板，Linux)
                    ┌─────────────────────────┐
                    │  new_infantry 控制代码    │
                    │  视觉自瞄算法 (可选)       │
                    └──┬──┬──┬──┬─────────────┘
                       │  │  │  │
           ┌───────────┘  │  │  └──────────┐
           ▼              ▼  ▼              ▼
       USB-CAN         USB-TTL ×3        以太网

           │              │  │

     ┌──────────┐   ┌────┐┌────┐┌────┐
     │ CAN 总线  │   │IMU ││IMU ││裁判│
     │          │   │CH10││HERO││系统│
     └────┬─────┘   └────┘└────┘└────┘
          │
    ┌─────┼─────┐
    ▼     ▼     ▼
  M6020 M3508 M2006  ...所有 DJI 电机 + 超级电容
```

## 二、主控板直接连接的设备

| 序号 | 连接对象 | 接口 | 设备路径 | 说明 |
|------|---------|------|---------|------|
| 1 | USB-CAN 模块 | USB | `can0`, `can1` | 1 个模块出 2 路 CAN |
| 2 | USB-TTL #1 | USB | `/dev/IMU_CH10X` (921600) | CH10X IMU，yaw 姿态 |
| 3 | USB-TTL #2 | USB | `/dev/IMU_HERO` (115200) | IMU (pitch) + 遥控器接收机 |
| 4 | USB-TTL #3 | USB | 裁判系统专用 | 裁判系统主控 (115200) |

最少需要 **3~4 个 USB 口**，不够加 USB Hub。

## 四、CAN 总线初始化（主控板上执行）

```bash
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can1 type can bitrate 1000000
sudo ip link set can0 up
sudo ip link set can1 up

# 验证
ip -details link show can0
# 应看到: state UP, bitrate 1000000
```

## 五、串口设备配置

### 创建软链接（如果没有 udev 规则）

```bash
sudo ln -s /dev/ttyUSB0 /dev/IMU_CH10X
sudo ln -s /dev/ttyUSB1 /dev/IMU_HERO
sudo chmod 777 /dev/ttyUSB* /dev/IMU_*
```

### 步兵配置（config_infantry.hpp:20-23）

```cpp
const std::vector<std::tuple<std::string, int, int>> SerialInitList = {
    { "/dev/IMU_HERO",   115200, 2000 },
    { "/dev/IMU_CH10X",  921600, 2000 }
};

const std::string rc_controller_serial = "/dev/IMU_HERO";  // 遥控器走这条线
```

### 云台 IMU 配置（config_infantry.hpp:56-57）

```cpp
.imu_serial_port = "/dev/IMU_CH10X",       // yaw IMU
.imu_serial_port_pitch = "/dev/IMU_HERO",  // pitch IMU
```

## 六、视觉自瞄连接

### 架构：视觉和控制可以在同一台 Mini PC 上

```cpp
// config_infantry.hpp:134
.auto_aim_ip = "127.0.0.1",     // localhost，同机通信
.auto_aim_port = 11453
```

视觉算法通过 UDP 向主控发送：
- **yaw / pitch 目标角度**
- **fire 开火指令**

主控通过 UDP 向视觉返回：
- **当前云台角度**
- **机器人颜色**

### 端口分配

| 端口 | 方向 | 内容 |
|------|------|------|
| 11451 | 主控监听 | 视觉 → 主控：自瞄控制 (`Auto_aim_control`) |
| 11453 | 视觉监听 | 主控 → 视觉：云台角度反馈 |
| 8080 | 上位机监听 | Logger 遥测数据 (UDP) |

## 七、硬件设备完整清单

### DJI 电机

| 型号 | 数量 | 用途 | 编码器 | 减速比 |
|------|------|------|--------|--------|
| M3508 | 6 | 底盘 ×4 + 摩擦轮 ×2 | 8192 线 | 19:1 |
| M6020 | 2 | 云台 yaw + pitch | 8192 线 | 1:1 |
| M2006 | 1 | 拨弹 | 8192 线 | 36:1 |

### 传感器与通信

| 设备 | 数量 | 接口 | 说明 |
|------|------|------|------|
| HiPNUC CH10X IMU | 1 | 串口 921600 | 工业级 MEMS，含 CRC16 |
| 通用 IMU | 1 | 串口 115200 | pitch + 遥控器共用 |
| 遥控器接收机 | 1 | 串口 (SBUS) | 16 通道 + 键鼠 |
| 裁判系统主控 | 1 | 串口 115200 | RoboMaster 官方 |
| 超级电容 | 1 | CAN | 功率缓冲 300W |

### 转接模块

| 模块 | 数量 | 说明 |
|------|------|------|
| USB-CAN 模块 | 1 | MCP2515 或类似，出 can0 / can1 |
| USB-TTL 串口模块 | 3 | 分别接 IMU×2 + 裁判系统 |

## 八、机器人启动流程

```
1. 上电 → Mini PC 启动 Linux
2. sudo ip link set can0/can1 up  (初始化 CAN)
3. sudo ./new_infantry             (运行控制程序)
       │
       ├── load_hardware()  打开 CAN/串口/Socket，启动 IO 读取线程
       ├── start_init()     注册回调，等待 IMU 上线 + 云台回中
       ├── init_join()      等待初始化完成
       │   → LOG_INFO("init finished!")
       ├── set_mode(ROBOT_FOLLOW_GIMBAL)
       ├── start()          启动底盘/云台/发射/裁判系统控制线程
       └── join()           阻塞主线程
```

## 九、车型编译切换

| 机型 | CMake 参数 | 差异 |
|------|-----------|------|
| 步兵 | `-DCONFIG_INFANTRY=1`（默认） | 麦轮底盘 + 单云台 + 17mm |
| 哨兵 | `-DCONFIG_SENTRY=1` | 双云台 + 轨道巡逻 + 无底盘 |
| 英雄 | `-DCONFIG_HERO=1` | 单云台 + 底盘 + 42mm |

编译时通过 `robot_type_config.hpp` 中的 `MUXDEF` 宏自动包含对应的 `config_xxx.hpp`。

## 一、核心数据结构：Robot_set（共享白板）

`Robot::Robot_set` 是整个系统的**唯一共享数据中心**，通过 `std::shared_ptr` 在所有模块间传递，各模块直接读写，无锁。

**定义位置**：[include/robot.hpp:8-84](../include/robot.hpp#L8-L84)

```
Robot_set
├── 【底盘指令】vx_set, vy_set, wz_set, spin_state
├── 【云台指令】gimbal{1,2,3}_{yaw,pitch}_set + offset
├── 【云台目标】gimbalT_{1,2}_{yaw,pitch}_set + yaw_reletive（视觉写入）
├── 【哨兵专用】gimbal_sentry_{yaw_set, yaw, yaw_reletive}, sentry_follow_gimbal
├── 【发射指令】friction_open, friction_real_state, cv_fire, shoot_open
├── 【自瞄状态】aimx/y/z, is_aiming, auto_aim_status
├── 【模式管理】mode, last_mode, inited, chassis_recover_mode
│   ├── set_mode() — 记录模式变更
│   └── mode_changed() — 检测是否切换了模式
├── 【裁判系统】referee_info（血量 / 功率限制 / 热量 / 剩余弹量 / 各模块供电状态）
└── 【超级电容】super_cap_info（电容能量 / 底盘功率限制）
```

### 机器人模式枚举

```cpp
enum ROBOT_MODE {
    ROBOT_NO_FORCE,       // 无力模式（初始化中/保护状态，电机置零）
    ROBOT_FINISH_INIT,    // 初始化完成
    ROBOT_FOLLOW_GIMBAL,  // 跟随云台（默认模式）
    ROBOT_SEARCH,         // 搜索模式（云台正弦扫描）
    ROBOT_IDLE,           // 待机
    ROBOT_NOT_FOLLOW      // 不跟随
};
```

### 裁判系统数据结构

裁判系统通过**串口**接收，帧格式：`0xA5 + header + cmd_id + data + CRC16`

核心数据包：

| cmd_id | 结构体 | 关键字段 |
|---|---|---|
| `0x0001` | `GameStatus` | 比赛阶段、剩余时间 |
| `0x0201` | `GameRobotStatus` | 血量、功率上限、**3个供电状态位** |
| `0x0202` | `PowerHeatData` | 底盘功率缓冲、枪管热量 |
| `0x0208` | `BulletAllowance` | 17mm/42mm剩余弹量 |

## 二、Robot_ctrl：组装者（不是父类）

**定义位置**：[include/robot_controller/robot_controller.hpp](../include/robot_controller/robot_controller.hpp)
**实现位置**：[src/robot_controller/robot_controller.cc](../src/robot_controller/robot_controller.cc)

### 2.1 Robot_ctrl 用组合（Composition），不是继承

```cpp
class Robot_ctrl {
public:
    std::shared_ptr<Robot_set> robot_set;    // 共享数据中枢

    Device::Rc_Controller rc_controller;     // 遥控器
    Device::Dji_referee referee;            // 裁判系统
    Chassis::Chassis chassis;               // 底盘
    Config::GimbalType gimbal;              // 云台（编译期决定类型）
    Gimbal::GimbalT gimbal_sentry;          // 哨兵第二云台
    Device::Super_Cap super_cap;            // 超级电容
};
```

- **没有继承关系**：`Robot_ctrl` 不继承任何模块，模块也不继承 `Robot_ctrl`
- 每个模块是 Robot_ctrl 的**成员变量**（has-a 关系）
- 各模块通过**共享 `robot_set`** 来协作

### 2.2 三步集成：声明 → 构造 → 连接

**第一步：声明成员变量**（.hpp 文件，见上）

**第二步：构造**（初始化列表）

```cpp
Robot_ctrl::Robot_ctrl()
    : rc_controller(Config::rc_controller_serial),  // "/dev/IMU_BIG_YAW"
      gimbal(Config::gimbal_config),                 // PID参数 + 电机型号 + 自瞄IP
      chassis(Config::chassis_config)                // 4个轮子的电机型号 + PID
{
    robot_set = std::make_shared<Robot_set>();       // 创建共享白板
}
```

- `:` 后面是**初始化列表**：调用每个成员的构造函数，传入配置参数
- `{}` 里面是**函数体**：此时所有成员已构造完毕，做额外初始化

**第三步：连接（注入共享数据）**

```cpp
void Robot_ctrl::start_init() {
    rc_controller.init(robot_set);   // 遥控器拿到 robot_set 指针 → 往里写指令
    referee.init(robot_set);         // 裁判系统拿到指针 → 往里写比赛数据
    chassis.init(robot_set);         // 底盘拿到指针 → 读速度指令
    gimbal.init(robot_set);          // 云台拿到指针 → 读角度指令 + 注册自瞄回调
}
```

每个模块的 `init()` 内部把 `shared_ptr` 存下来，之后就可以直接读写。

### 2.4 线程生命周期

```cpp
load_hardware()  // 创建 CAN/Serial/Socket → 启动 IO 读写线程
    ↓
start_init()     // 启动云台初始化线程（等待 IMU 上线 + 回中）
    ↓
init_join()      // 等待初始化完成
    ↓
start()          // 启动所有主循环线程（云台、底盘、裁判系统）
    ↓
join()           // 阻塞主线程
```

### 2.5 编译期机型选择（不用虚函数）

```cpp
// 编译时传宏：-DCONFIG_SENTRY 或 -DCONFIG_INFANTRY 或 -DCONFIG_HERO

// robot_type_config.hpp 根据宏包含不同配置：
#include MUXDEF(CONFIG_SENTRY, "config_sentry.hpp",
        MUXDEF(CONFIG_HERO, "config_hero.hpp",
        MUXDEF(CONFIG_INFANTRY, "config_infantry.hpp", "config_fallback.hpp")))

// sentry 配置里:  using GimbalType = Gimbal::GimbalSentry;  // 双头云台
// infantry 配置:  using GimbalType = Gimbal::GimbalT;        // 单头云台
// hero 配置:      using GimbalType = Gimbal::GimbalT;        // 单头云台
```

然后在 `Robot_ctrl` 里用 `Config::GimbalType gimbal;` — 编译期决定类型，零运行时开销。

代码中散布 `MUXDEF` / `IFDEF` 宏来处理机型差异（比如只有哨兵才创建 `gimbal_sentry`）。

## 三、IO 层（血管系统）

### 3.1 架构总览

```
                IO::IO<T> 管理器（全局模板单例）
                ├── io<CAN>    — 3条 CAN 总线
                ├── io<SERIAL> — 2个串口
                └── io<SOCKET> — 1个 UDP Socket
                         │
        每个 io<T> 是一个 unordered_map<string, T*>
        insert() 时为每个设备启动独立的 task() 线程
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
  Can_interface    Serial_interface  Server_socket_interface
  (SocketCAN)      (UART)            (UDP :11451)
        │                │                │
        ▼                ▼                ▼
  [电机 x12]      [IMU x2]         [视觉自瞄]
  [超级电容]      [遥控器]         [导航系统]
                  [裁判系统]
```

### 3.2 CAN 总线

**头文件**：[include/io/can.hpp](../include/io/can.hpp)
**实现**：[src/io/can.cc](../src/io/can.cc)

```cpp
class Can_interface : public Callback_key<uint32_t, can_frame> {
    // 注册回调：register_callback_key(CAN_ID, function)
    // 读取循环：task() { while(1) { read(); callback_key(id, frame); } }
    // 发送：send(can_frame)
};
```

- 封装 Linux SocketCAN API（`socket()` + `ioctl()` + `bind()` + `read()`/`write()`）
- 收到 CAN 帧后按 `can_id` 分发回调
- 发送失败累计 2000 次会记录错误日志

**CAN 帧分发示例**（DJIMotorManager）：

```cpp
// 电机注册回调（按 CAN ID）
can->register_callback_key(0x201, [&](const can_frame &frame) {
    motor.unpack(frame);  // 解析转子角度、转速、温度
});

// 电机发送（DJIMotorManager 每毫秒打包4个电机的电流）
can->send({.can_id = 0x200, .len = 8, .data = {...}});
```

### 3.3 串口

**头文件**：[include/io/serial_interface.hpp](../include/io/serial_interface.hpp)
**实现**：[src/io/serial_interface.cc](../src/io/serial_interface.cc)

```cpp
class Serial_interface : public serial::Serial, 
                         public Callback<ReceivePacket_IMU, ReceivePacket_RC_CTRL> {
    // 注册回调：register_callback<ReceivePacket_IMU>(fn)
    // 读取循环：task() 中解析两种协议（旧协议 0x55AA / CH10X 0x5AA5）
    // 发送：send<T>(data)
};
```

- 一条串口线上同时承载 IMU 和遥控器数据，通过 `pkg_id` 区分
- 支持两种 IMU 协议：旧版 0x55AA 头、新版 CH10X（含 CRC16）
- 回调按**类型**分发：`callback(imu_pkg)` 或 `callback(rc_pkg)`

### 3.4 UDP Socket

**头文件**：[include/io/socket_interface.hpp](../include/io/socket_interface.hpp)
**实现**：[src/io/socket_interface.cc](../src/io/socket_interface.cc)

```cpp
class Server_socket_interface : public Callback<ReceiveNavigationInfo>,
                                public Callback_key<uint8_t, Auto_aim_control> {
    // 注册回调：register_callback_key(0x6A, fn)
    // 读取：recvfrom() → 按 header 字节分发
    // 发送：sendto() → 已注册的客户端地址
};
```

- UDP 端口 11451
- `header == 0x37` → 导航数据
- 其他 header → 自瞄控制（`Auto_aim_control`）
- 客户端地址在首次收到包时自动注册

### 3.5 回调系统

**文件**：[include/io/io_callback.hpp](../include/io/io_callback.hpp)

两种机制：

| 机制 | 用途 | 示例 |
|---|---|---|
| `Callback<Type1, Type2>` | 按**类型**分发（编译期） | Serial：IMU 和 RC 共用一条线，按类型分开 |
| `Callback_key<Key, Args>` | 按**键值**分发（运行时） | CAN：按 CAN ID 发给不同电机；Socket：按 header 字节 |

```cpp
// 类型分发
class Serial_interface : public Callback<IMU_Packet, RC_Packet> {
    register_callback<IMU_Packet>(fn);   // 收到 IMU 数据 → 调 fn
    register_callback<RC_Packet>(fn);    // 收到遥控数据 → 调 fn
};

// 键值分发
class Can_interface : public Callback_key<uint32_t, can_frame> {
    register_callback_key(0x201, fn);    // CAN ID=0x201 → 调 fn
    register_callback_key(0x202, fn);    // CAN ID=0x202 → 调 fn
};
```

## 四、各模块如何连接 IO 层

### 4.1 电机 (DJIMotor)

```cpp
// DJIMotorManager::register_motor()
auto can = IO::io<CAN>[motor.can_info.can_name_];   // 通过名字找到 CAN 接口
can->register_callback_key(motor.can_info.callback_flag, [&](frame) {
    motor.unpack(frame);  // 电机收到 CAN 帧 → 更新角度、转速
});
```

所有电机由 `DJIMotorManager::task()` 统一管理：每 1ms 打包电流指令 → CAN 发送。

### 4.2 IMU（惯性测量单元）

```cpp
// IMU::enable()
auto serial = IO::io<SERIAL>[serial_name];          // 通过名字找到串口
serial->register_callback<ReceivePacket_IMU>([&](pkg) {
    this->unpack(pkg);  // 收到 IMU 数据 → 更新 yaw/pitch/roll
});
```

### 4.3 遥控器 (Rc_Controller)

```cpp
// Rc_Controller::init()
auto serial = IO::io<SERIAL>[serial_name];
serial->register_callback<ReceivePacket_RC_CTRL>([&](pkg) {
    this->unpack(pkg);  // 解析摇杆/开关 → 写入 robot_set->vx_set 等
});
```

### 4.4 视觉自瞄

```cpp
// GimbalT::init() 中注册
auto socket = IO::io<SOCKET>["AUTO_AIM_CONTROL"];
socket->add_client(config.header, config.auto_aim_ip, config.auto_aim_port);
socket->register_callback_key(config.header, [&](const Auto_aim_control &vc) {
    *yaw_set = vc.yaw_set;     // 视觉给的目标角度
    *pitch_set = vc.pitch_set;
    robot_set->cv_fire = vc.fire;  // 视觉给的开火指令
});
```

## 六、线程模型

| 线程 | 启动位置 | 功能 | 频率 |
|---|---|---|---|
| `Can_interface::task()` ×3 | `load_hardware()` | 读 CAN 帧 → 分发回调 | 阻塞读 |
| `Serial_interface::task()` ×2 | `load_hardware()` | 读串口 → 解析协议 → 回调 | 阻塞读 |
| `Socket::task()` | `load_hardware()` | recvfrom → 解析 → 回调 | 阻塞读 |
| `DJIMotorManager::task()` | `start_init()` | 打包电机电流 → CAN 发送 | 1kHz |
| `Chassis::task()` | `start()` | 速度分解 → PID → 写电机电流 | 500Hz |
| `GimbalT::task()` ×N | `start()` | 双环PID + 发包给视觉 | 1kHz |
| `Shoot::task()` ×N | 云台线程内 | 摩擦轮+拨弹控制 | 1kHz |
| `Dji_referee::task()` | `start()` | 读裁判串口 → 解包 | 1kHz |
| `Dji_referee::task_ui()` | `start()` | 更新裁判系统屏幕 UI | — |

## 七、关键设计模式

1. **共享白板（Shared State）**：`Robot_set` 以 `shared_ptr` 传递，无锁，零拷贝
2. **组合优于继承**：Robot 拥有 Chassis、Gimbal、Shoot 作为成员，不继承它们
3. **编译期多态**：用 `MUXDEF` / `IFDEF` 宏在编译时选择机型行为，零运行时开销
4. **回调注册**：设备不直接读硬件，而是向 IO 层注册回调，IO 线程负责分发
5. **字符串索引**：IO 资源通过名字查找（如 `io<CAN>["CAN_CHASSIS"]`），类似服务发现
6. **Controller 管道**：`float >> PidRad >> PidPosition >> motor.set()` 串联控制器
7. **独立线程模型**：每个模块独立线程，通过共享数据通信，无锁竞争

Can_interface::Can_interface(const std::string &name) : name(name) {

// can.cc:20-46
void Can_interface::init(const char *can_channel) {
    // ① 创建 Linux CAN socket
    soket_id = socket(PF_CAN, SOCK_RAW, CAN_RAW);
    // ② 设置接口名（如 "can0"）
    strcpy(ifr->ifr_name, can_channel);
    // ③ 获取接口索引
    ioctl(soket_id, SIOCGIFINDEX, ifr);
    // ④ 绑定
    addr->can_family = AF_CAN;
    addr->can_ifindex = ifr->ifr_ifindex;
    bind(soket_id, (sockaddr *)addr, sizeof(*addr));
    // ⑤ 标记就绪
    init_flag = true;
}
现在：一个 Can_interface 对象创建好了，Linux CAN socket 已打开并绑定。

load_hardware() 完整执行结果

load_hardware() 执行前:
  io<CAN>:
    data = {}             ← 空 map
    threads = []           ← 无线程

load_hardware() 执行中 — 第 1 轮（name = "CAN_CHASSIS"）:
  ① new Can_interface("CAN_CHASSIS")
     └→ socket() + ioctl() + bind()     ← 打开硬件
  ② data["CAN_CHASSIS"] = &对象
  ③ 起线程: Can_interface::task() 开始跑 ← 开始 read()

load_hardware() 执行中 — 第 2 轮（name = "CAN_GIMBAL"）:
  ① new Can_interface("CAN_GIMBAL")
  ② data["CAN_GIMBAL"] = &对象
  ③ 起线程: 又一个 task() 开始跑

load_hardware() 执行中 — 第 3 轮（name = "CAN_BULLET"）:
  ① new Can_interface("CAN_BULLET")
  ② data["CAN_BULLET"] = &对象
  ③ 起线程: 又一个 task() 开始跑

  串口和 Socket 同理...

load_hardware() 执行后:
  io<CAN>:
    data = {
      "CAN_CHASSIS" → Can_interface 对象①
      "CAN_GIMBAL"  → Can_interface 对象②
      "CAN_BULLET"  → Can_interface 对象③
    }
    threads = [task①, task②, task③]  ← 三个线程在死循环 read()
一句话总结

load_hardware()
  → for 每个名字
      → new 一个 IO 设备对象（顺便调 init() 打开硬件）
      → 存进全局字典（以后通过名字查找）
      → 起一个线程跑 task()（死循环 read）
此时 6 个 task() 线程都在跑了，但收到的数据没人处理——因为还没有设备注册回调。下一步 start_init() 才来做这件事。

load_hardware()是对整个机器进行还是只是对一个部分，比如云台
对整个机器。load_hardware() 一次性初始化所有 6 条 IO 通道：


void Robot_ctrl::load_hardware() {
    // 3 条 CAN          → 底盘用、云台用、发射用 — 全建了
    for (auto& name : Config::CanInitList) {
        IO::io<CAN>.insert(name);
    }
    // 2 个串口          → IMU 用、遥控器+裁判用 — 全建了
    for (auto& [name, baud, timeout] : Config::SerialInitList) {
        IO::io<SERIAL>.insert(name, baud, timeout);
    }
    // 1 个 Socket       → 视觉自瞄用 — 也建了
    for (auto& name : Config::SocketInitList) {
        IO::io<SOCKET>.insert(name);
    }
}
它不在乎谁用，先把全部管道铺好：


CAN_CHASSIS  ← 底盘用，但管你底盘用不用，先建了
CAN_GIMBAL   ← 云台用，同理
CAN_BULLET   ← 发射用，同理
/dev/IMU_SMALL_YAW ← IMU 用
/dev/IMU_BIG_YAW   ← IMU + 遥控器用
AUTO_AIM_CONTROL   ← 视觉用
打个比方：


load_hardware() = 装修时铺水管电线（全屋一起铺）
start_init()    = 把水龙头、灯泡接到对应的管道上（每个模块各接各的）
load_hardware() 完之后，6 个 task() 线程都在跑了，但谁也没注册回调——就像水管里有水在流，但没接水龙头，水白流了。下一步 start_init() 才让云台、底盘等各自找到自己的管道、注册回调。

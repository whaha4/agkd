# 车型选择机制：宏 + Config 文件

## 一句话

**编译时通过 `-D` 宏二选一，选中一个 `config_xxx.hpp`，同一个 `Config::` 名字在不同文件里填了不同的值，代码逻辑完全不变。**

---

## 一、整体流程

```
构建命令                             代码层
─────────                          ────────

make hero                          所有 .cc 文件
  │                                  │
  └─→ g++ -DCONFIG_HERO=1            ├─ #include "robot_type_config.hpp"
        │                            │     │
        ▼                            │     └─ MUXDEF 嵌套选择 → #include "config_hero.hpp"
        ┌──────────────────┐         │
        │ robot_type_config │         ├─ Config::CanInitList = {"CAN_CHASSIS", "CAN_GIMBAL"}
        │   .hpp            │         ├─ Config::chassis_config = {英雄的PID, 英雄的电机...}
        │                   │         ├─ Config::gimbal_config  = {英雄的云台...}
        │  MUXDEF(           │         │
        │   CONFIG_SENTRY,   │         └─ 编译成英雄二进制
        │   "sentry.hpp",    │
        │   MUXDEF(          │
        │    CONFIG_HERO,    │
        │    "hero.hpp",     │
        │    MUXDEF(          │
        │     CONFIG_INFANTRY,│
        │     "infantry.hpp",│
        │     "fallback.hpp" │
        │  )))               │
        └──────────────────┘
```

## 二、入口：robot_type_config.hpp

位置：[include/configs/robot_type_config.hpp](../GKD_Control/include/configs/robot_type_config.hpp)

```cpp
#include MUXDEF(CONFIG_SENTRY, "config_sentry.hpp",
         MUXDEF(CONFIG_HERO, "config_hero.hpp",
         MUXDEF(CONFIG_INFANTRY, "config_infantry.hpp",
                               "config_fallback.hpp")))
```

**嵌套选择链**：哨兵 → 英雄 → 步兵 → fallback。找到第一个已定义的宏，`#include` 对应的头文件。

三个车型宏只有一个被定义（编译时 `-D` 注入），所以只有一份 config 被引入。

## 五、MUXDEF 宏原理

来自 [macro_helpers.hpp](../GKD_Control/include/utils/macro_helpers.hpp)。

**原理**：宏定义了 → 展开带逗号 → `CHOOSE2nd` 选第1个参数。宏没定义 → 没有逗号 → `CHOOSE2nd` 选第2个参数。

```cpp
// 宏已定义时 (CONFIG_HERO=1):
MUXDEF(CONFIG_HERO, A, B)  →  A   ✅

// 宏未定义时:
MUXDEF(CONFIG_HERO, A, B)  →  B   ✅
```

关键实现链条：

```cpp
#define __P_DEF_1  X,     // 占位符，宏=1时拼接结果带逗号
#define CHOOSE2nd(a, b, ...) b    // 始终选第2个
#define MUXDEF(macro, X, Y) \
    MUX_MACRO_PROPERTY(__P_DEF_, macro, X, Y)

// CONFIG_HERO=1 时的展开：
// concat(__P_DEF_, CONFIG_HERO) → __P_DEF_1 → "X,"
// → MUX_WITH_COMMA(X,, A, B) → CHOOSE2nd(X, , A, B) → A

// CONFIG_HERO 未定义：
// concat(__P_DEF_, CONFIG_HERO) → __P_DEF_CONFIG_HERO (普通token,无逗号)
// → MUX_WITH_COMMA(__P_DEF_CONFIG_HERO, A, B)
// → CHOOSE2nd(__P_DEF_CONFIG_HERO A, B) → B
```

## 六、相关宏一览

| 宏 | 作用 | 示例 |
|----|------|------|
| `MUXDEF(M, A, B)` | M已定义→A，否则→B | `MUXDEF(CONFIG_HERO, hero.hpp, infantry.hpp)` |
| `MUXNDEF(M, A, B)` | M未定义→A，否则→B | 与MUXDEF相反 |
| `IFDEF(M, code)` | M已定义才保留code | `IFDEF(CONFIG_SENTRY, sentry.func();)` |
| `IFNDEF(M, code)` | M未定义才保留code | `IFNDEF(CONFIG_SENTRY, infantry.func();)` |
| `ISDEF(M)` | M已定义→1，否则→0 | `if (ISDEF(CONFIG_SENTRY))` |

## 七、如何切换车型

三种方式，本质都是给编译器传 `-D`：

```bash
# Makefile（推荐）
make hero       # → -DCONFIG_HERO=1
make infantry   # → -DCONFIG_INFANTRY=1
make sentry     # → -DCONFIG_SENTRY=1

# CMake — 改 CMakeLists.txt 第15行
add_compile_options(-DCONFIG_HERO=1)

# xmake
xmake f --type=hero && xmake
```

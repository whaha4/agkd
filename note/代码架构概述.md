## 一、项目概述

GKD 是**RoboMaster 机甲大师赛**的机器人嵌入式控制代码，支持哨兵（sentry）、步兵（infantry）、英雄（hero）三种机型。采用 **C++** 开发，编译工具支持 GNU Make、CMake 和 XMake，可在 Linux/RTOS 上运行，官方推荐 Docker 开发环境。

## 三、程序入口 main.cc

```cpp
int main(int argc, char **argv) {
    Robot::Robot_ctrl robot;        // 创建机器人控制器
    robot.load_hardware();          // 初始化 CAN/串口/Socket 硬件
    robot.start_init();             // 启动各模块初始化线程（等待IMU、云台回中）
    robot.init_join();              // 等待初始化完成
    robot.robot_set->set_mode(Types::ROBOT_MODE::ROBOT_FOLLOW_GIMBAL); // 默认跟随云台模式
    robot.start();                  // 启动各模块主循环线程
    robot.join();                   // 阻塞主线程
}
```

**关键流程**：硬件加载 → 分模块初始化 → 启动主循环。

## 四、核心数据结构 robot.hpp

`Robot::Robot_set` 是整个系统的**共享数据中枢**（通过 `shared_ptr` 在各模块间传递），包含：

| 模块 | 关键字段 | 说明 |
|------|---------|------|
| 底盘 | `vx_set`, `vy_set`, `wz_set` | 目标速度（世界坐标系） |
| 云台 | `gimbalT_1/2_yaw_set`, `gimbalT_1/2_pitch_set` | 目标角度（弧度） |
| 发射 | `friction_open`, `cv_fire`, `shoot_open` | 摩擦轮/拨弹/视觉开火 |
| 裁判系统 | `referee_info` | 血量、功率、热量、剩余弹量 |
| 超级电容 | `super_cap_info` | 电容能量状态 |

## 五、各模块详解

### 5.1 底盘 (chassis/)

**文件**：`src/chassis/chassis.cc`

**职责**：控制四个麦克纳姆轮的运动，实现**跟随云台**（底盘不动、云台转）和**自由移动**两种模式。

**核心逻辑**：
1. **速度分解**：`decomposition_speed()` — 将世界坐标系速度 `(vx, vy)` 转换到车身坐标系，加上旋转角速度 `wz`，再分解到四个轮子（麦轮运动学逆解）。
2. **功率限制**：`power_manager` — 实时监控四个电机的功率，通过 PID 限幅防止超功率（哨兵规则限制）。
3. **回中恢复**：当云台指令停止时，底盘自动缓慢旋转将车身"回正"。
4. **离线保护**：底盘裁判系统电源被切断时，强制所有电机归零。

```cpp
// 麦轮速度分解（逆运动学）
wheel_speed[0] = -vx_set - vy_set + wz_set;  // 左前轮
wheel_speed[1] = -vx_set + vy_set + wz_set;  // 右前轮
wheel_speed[2] =  vx_set - vy_set + wz_set;  // 左后轮
wheel_speed[3] =  vx_set + vy_set + wz_set;  // 右后轮
```

**辅助模块**：`power_controller.cc` — 功率管理，包含功率上限、缓冲能量计算、错误标志等。

---

### 5.2 云台 (gimbal/)

**文件**：`src/gimbal/gimbal_temp.cc`（通用版）/ `gimbal_sentry.cc`（哨兵版）

**职责**：控制云台的 yaw（偏航）和 pitch（俯仰），使用双 IMU（分别测 yaw/pitch 角度）做闭环控制。

**控制架构（串级 PID）**：
```
外环（角度环）：yaw_absolute_pid / pitch_absolute_pid
  → 目标角速度
内环（角速度环）：yaw_rate_pid / pitch_rate_pid
  → 电机电流指令
```

**关键功能**：
- **初始化回中**：等待电机和 IMU 上线，然后驱动云台缓慢回到中立位置，检测到稳定后标记初始化完成。
- **双头哨兵**：哨兵有两条云台，`gimbal_id=1` 和 `gimbal_id=2`，分别对应两个摄像头（自瞄/大符）。
- **自瞄接收**：通过 Socket 接收视觉算法的自瞄目标角度 (`Auto_aim_control`)，300ms 内无数据自动停止射击。
- **搜索模式**：`ROBOT_SEARCH` 模式下云台做正弦轨迹扫描。

**数据更新**：
```cpp
yaw_relative = rad_format(yaw_motor.data_.rotor_angle - offset);  // 电机相对角度
yaw_gyro = cos(pitch) * imu_yaw.yaw_rate - sin(pitch) * imu_yaw.roll_rate;  // 角速度（投影修正）
```

### 5.3 发射 (shoot/)

**文件**：`src/shoot/shoot.cc`

**职责**：控制摩擦轮电机和拨弹电机，实现弹丸射出。

**组件**：
- `left_friction` / `right_friction`：左/右摩擦轮，使用 `friction_ramp` 斜坡启动，防止电流冲击
- `trigger`：拨弹电机，按固定速度连续拨弹

**核心逻辑**：
1. **摩擦轮启动**：接收 `friction_open` 指令，斜坡升速到 `FRICTION_MAX_SPEED`
2. **热量/弹量限制**：从裁判系统读取当前热量和剩余弹量，超限禁止射击
3. **卡弹检测**：`isJam()` — 电流>4000且转速<1时判定为卡弹，停止拨弹一段时间
4. **摩擦轮真实状态**：`friction_real_state` — 通过摩擦轮实际线速度判断是否已达速（>0.5 m/s）

---

### 5.4 裁判系统 (device/referee/)

**文件**：`src/device/referee/referee.cc`

**职责**：通过**串口**接收裁判系统主控机的 UDP-over-serial 协议包，解析并更新 `referee_info`。

**协议帧格式**：
```
0xA5 + header + cmd_id + data + CRC16
```
通过 `cmd_id` 区分不同数据包类型：
- `GAME_STATUS_CMD`：比赛状态（阶段、剩余时间）
- `ROBOT_STATUS_CMD`：机器人状态（血量、功率限制）
- `POWER_HEAT_DATA_CMD`：实时功率和热量
- `BULLET_REMAINING_CMD`：剩余弹量
- `REFEREE_WARNING_CMD`：裁判警告

裁判系统是**单向**的（只接收），通过串口 DMA 接收，主线程每毫秒轮询读取缓冲区并解包。

### 5.5 通信 IO (io/)

**CAN**：`src/io/can.cc`
- 封装 Linux SocketCAN API
- `send(can_frame)` — 发送标准 CAN 帧
- `callback_key(id, frame)` — 按 CAN ID 分发到对应设备的回调

**Socket**：`src/io/socket_interface.cc`
- 用于与**视觉算法**通信（自瞄控制：`AUTO_AIM_CONTROL`）
- 支持 UDP 广播/单播，注册回调函数处理接收数据

**Serial**：`src/io/serial_interface.cc`
- 用于与 **IMU** 和**裁判系统**通信
- 封装 `serial` 第三方库，支持配置波特率、超时

### 5.6 机器人总控制器 (robot_controller/)

**文件**：`src/robot_controller/robot_controller.cc`

`Robot_ctrl` 是整个系统的"组装者"：

```cpp
Robot_ctrl() : 
    rc_controller(...),   // 遥控器
    gimbal(...),          // 云台（主）
    chassis(...),          // 底盘
    gimbal_sentry(...)    // 云台（哨兵双头，仅哨兵机型）
```

**线程启动**：
- `start_init()`：启动初始化线程（IMU等待、云台回中），注册 CAN/串口/Socket 硬件
- `start()`：正式启动所有模块主循环线程（云台、底盘、裁判系统）

## 八、视觉通信协议 (robot.hpp 中的数据包)

系统通过 Socket 与视觉算法交互：

| 包名 | 方向 | 内容 |
|------|------|------|
| `ReceiveGimbalPacket` (0x5A) | ← 视觉接收 | 自瞄目标角度、追踪状态、装甲板数量 |
| `SendAutoAimInfo` (0xA6) | → 视觉发送 | 当前云台角度、己方颜色 |
| `Auto_aim_control` (0x6A) | ← 视觉接收 | yaw/pitch 指令、fire 指令 |
| `SendVisionControl` | → 视觉发送 | 云台角度（冗余） |

## 十、关键设计思想

1. **共享数据结构中枢**：`Robot_set` 以 `shared_ptr` 在所有模块间共享，避免锁竞争
2. **条件编译代替继承**：用 `MUXDEF` 宏在不同机型间切换，无需虚函数开销
3. **串级 PID**：外环角度环 + 内环角速度环，控制频率内环高于外环
4. **硬件抽象**：CAN/Serial/Socket 统一封装为 `IO` 接口，支持热插拔
5. **独立线程模型**：每个模块（底盘、云台、发射、裁判系统）各自运行独立线程，通过共享数据通信

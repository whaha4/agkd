方案：通过 config_project.hpp 实现 Chassis-Only 模式
Context
用户只有底盘（4 个 M3508 麦轮），CAN 接口叫 CAN_CHASSIS，无云台/IMU/遥控器/裁判系统。希望复用 GKD_Control 的 config 模式（类似 config_infantry.hpp），通过新建 config_project.hpp 加少量改动让程序在只有底盘的情况下运行。

问题分析
仅写 config 文件不够。原因是 robot_controller.hpp 和 robot_controller.cc 硬编码了云台、遥控器、裁判系统等模块的构造和初始化。需要同步修改。

需要改动的文件（共 5 个）
1. 新建 config_project.hpp
路径: agkd/GKD_Control/include/configs/config_project.hpp

参照 config_infantry.hpp 的模式，但只保留底盘配置：

using GimbalType = Gimbal::GimbalT;（编译占位，实际不跑）
CanInitList = { "CAN_CHASSIS" } — 只有一根 CAN
SocketInitList = {} — 无视觉
SerialInitList = {} — 无串口设备
rc_controller_serial = "" — 无遥控器
chassis_config — 4 个 M3508，CAN_CHASSIS，ID 1~4
2. 修改 robot_type_config.hpp
路径: agkd/GKD_Control/include/configs/robot_type_config.hpp

在 MUXDEF 链最前面加入 CONFIG_PROJECT 分支：

#include MUXDEF(CONFIG_PROJECT, "config_project.hpp",
    MUXDEF(CONFIG_SENTRY, "config_sentry.hpp",
    MUXDEF(CONFIG_HERO, "config_hero.hpp",
    MUXDEF(CONFIG_INFANTRY, "config_infantry.hpp", "config_fallback.hpp"))))
3. 修改 robot_controller.hpp
路径: agkd/GKD_Control/include/robot_controller/robot_controller.hpp

用 IFNDEF(CONFIG_PROJECT, ...) 包裹不需要的成员：

rc_controller — 无遥控器时不需要
referee — 无裁判系统时不需要
gimbal — 无云台时不需要（但保留占位类型）
super_cap — 无超级电容时不需要
4. 修改 robot_controller.cc
路径: agkd/GKD_Control/src/robot_controller/robot_controller.cc

用 IFNDEF(CONFIG_PROJECT, ...) 包裹：

构造函数初始化列表中的 rc_controller/gimbal
start_init() 中的 rc_controller/referee/gimbal/super_cap 初始化调用
start() 中的 gimbal/referee 线程启动
start_init() 末尾添加：IFDEF(CONFIG_PROJECT, robot_set->inited = Types::INIT_FINISH;) 跳过云台回中等候
5. 新建 chassis_keyboard.cpp（键盘控制）
路径: agkd/GKD_Control/src/support/chassis_keyboard.cc

在 CONFIG_PROJECT 模式下，没有遥控器输入，需要一个非阻塞键盘读取线程来向 robot_set 写入速度指令（WASD 移动、QE 旋转、空格急停）。

6. 修改 CMakeLists.txt
路径: agkd/GKD_Control/CMakeLists.txt

add_compile_options(-DCONFIG_PROJECT=1)
不改的文件
ControlLib/ — 完全不动
chassis.cc / chassis.hpp — 不动，它依赖的 gimbalT_1_yaw_reletive 始终为 0，在无云台时没问题
gimbal_temp.cc — 不动，CONFIG_PROJECT 下不会调用它的 init_task
所有 device 文件、shoot 文件 — 不动
关键设计决策
保留 GimbalType 别名：robot_controller.hpp 中 Config::GimbalType gimbal; 在 CONFIG_PROJECT 下会被 IFNDEF 排除，但 config 文件中仍需要 using GimbalType = ... 以保证类型系统完整（其他地方可能引用）
键盘控制作为独立线程：在 start() 中启动，写入 robot_set->vx_set/vy_set/wz_set，chassis 正常读取
不删除 chassis 中云台相关代码：decomposition_speed() 中 gimbalT_1_yaw_reletive 始终为 0，sincosf(0, ...) = (0, 1)，车身坐标系 = 世界坐标系，行为正确
验证方式
cd ~/gkd/agkd/GKD_Control/build
cmake .. && make -j$(nproc)
sudo ./new_infantry
预期：

启动打印 "init finished!"
键盘 W/A/S/D 控制小车移动
Q/E 旋转，空格急停
candump CAN_CHASSIS 可看到 0x200 帧发出电流指令
